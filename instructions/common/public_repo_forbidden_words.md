# 公開リポジトリ向け 禁則語の仕組み(正本・cmd_788 / cmd_797)

`origin` は公開リポジトリである。ここへ載せる差分・木・commit message に、個別業務に由来する
名称や個人識別子を混入させないため、commit 前に禁則語で走査する。

★**本ファイルは具体語を一切持たない。** 禁則語の正本リストそのものが業務由来の語と意味の説明を
載せていると、公開リポジトリへ名前を載せることになる(cmd_797 で撤去した)。本ファイルが公開するのは
**仕組み**(書式・許可ドメイン・ローカル拡張の説明)だけであり、具体語は git 管理外の
ローカル拡張だけが持つ(下記「ローカル拡張」)。

- 走査は `scripts/public_repo_scan.sh`(`/usr/bin/grep` フルパス・大小無視・ERE)が行う。
- 本ファイルは走査の入力(書式・許可ドメイン)を持つため、走査は本ファイル**1本のみ**を自己除外する
  (`instructions/common/public_repo_forbidden_words.md`。同名の別パスは除外しない)。
- 本ファイルは `scripts/build_instructions.sh` の取り込み対象ではない(生成物に混ざらない)。
- 本ファイルは 2 種類の fenced block を持つ: `forbidden-regex`(番兵・ちょうど1個)と
  `allowed-email-domains`(許可ドメイン・0個か1個)。

## 正規表現(番兵・1行)

下の `forbidden-regex` ブロックの**ちょうど1行**が正本である(ブロックが0個・2個以上、
またはブロック内が複数行なら script はエラー終了する)。`/usr/bin/grep -i -E` にそのまま渡せる形で書く。

公開側のこの行は**番兵**であり、実在の文には一致しない(自分自身の表記にも一致しないよう、
文字クラスで綴りを割ってある)。具体語をここへ足してはならない。

```forbidden-regex
no-real-word-sentinel[-]7c1e9a
```

★**fail-closed**: script はこの行が番兵と一致するか(=公開側が番兵のみか)を見る。公開側が番兵のみで、
かつローカル拡張に有効な語が1つも無いとき、script は**黙って通さず**、理由を表示して終了コード 2 で止まる。
具体語が1つも無い走査は、0 件でも「混入が無い」ことを何も意味しないためである。
(この行を具体語へ書き換えて回避してはならない。具体語は常にローカル拡張へ置く。)

## 許容(残留 OK・禁則の対象外)★殿確定 2026-09-30

次の3種は公開リポジトリに残ってよく、走査で検出しない(`cmd_789` の浄化対象にもしない)。

| 許容 | 扱い |
|------|------|
| `/home/kato`(個人環境の絶対 home path) | 禁則語ではない(ローカル拡張にも入れない) |
| `cmd_xxx` 形式の識別子(`cmd_788` 等) | 禁則語ではない(そもそも該当語が無い) |
| `v-sync.co.jp` のアドレス(自社ドメイン) | 許可ドメインとして走査前に**ドメイン部分だけ**を除去してから照合する |

★許可の除去は「許可ドメインの表記」だけを消す。同じ行にある禁則語は消さない。たとえば自社ドメイン宛の
アドレスは許容だが、社名だけが現れる表記(組織名など)、サブドメイン(`<禁則語>.<自社ドメイン>`)、
局部に禁則語を含むアドレス(`<禁則語>-team@<自社ドメイン>`)、`<自社ドメイン>.<他ドメイン>` のような
紛らわしい表記は、ローカル拡張の語で引き続き検出される。除去は次の形に限る:

- `@<許可ドメイン>` の直後が「英数字・`.`・`-` 以外」または行末(文末の `.` は可)であること
- 単独の `<許可ドメイン>`(URL のホスト等)は、直前が「英数字・`@`・`-` 以外」または行頭で、直後が上と同じであること
  (`@` の直後は上の形が扱う)

### 許可リストの範囲(★機械では「業務繋がり」を判定できない)

「業務で用いた固有名詞(プロジェクト・商品・顧客・倉庫・店舗名等)」と「自社ドメイン以外の**業務繋がり**の
ドメイン・メールアドレス」は是正対象である。だが「業務繋がりか」は機械で判定できない。そこで:

- メールアドレス(`局部@ドメイン`)をすべて抽出し、ドメインが下の `allowed-email-domains` に**無い**ものを
  **要確認(WARN)** として別出力する。WARN は **exit 0 のまま**件数を出す(NG にしない)。
- WARN を NG(exit 1)にしない理由: 機械が判定できるのは「許可リストにあるか」だけで、リスト外=業務繋がりとは
  限らない(第三者の公開アドレス・OSS の作者表記・`user@1000.service` のようなメールでない文字列が混じる)。
  NG にすると許可済みの内容まで止めて commit を滞留させ、この道具の目的(滞留の防止)に反する。
  WARN は SOP が要求する**人の目視確認**の入口であり、走査報告に件数(ディレクトリ別)を載せて判断する。
- 許可リストに足すときは、その根拠をコメント行(`#`)で残す(根拠のないドメインを足さない)。

```allowed-email-domains
# 許可ドメイン(1行に1ドメイン・小文字・完全一致。空行と # で始まる行は無視する)。
# ★足すときは根拠のコメントを添える。サブドメインは別エントリとして書く。
#
# 自社(殿確定 2026-09-30): 自社ドメインのアドレスは残留 OK。社名に由来する禁則語の例外はこの1件のみ。
v-sync.co.jp
# RFC 2606 / RFC 6761 の予約ドメイン: 実在しない例示・試験用で、業務と結びつかない。
example.com
example.org
example.net
example.invalid
# 開発ツール: GitHub の noreply アドレス(commit 作者・Co-Authored-By 行)。業務固有ではない。
github.com
users.noreply.github.com
# 開発ツール: AI 開発ツールの Co-Authored-By 行(noreply)。業務固有ではない。
anthropic.com
```

## ローカル拡張(具体語の唯一の置き場)

★**具体語(取引先名・委託先名・商品名・拠点名・Google Chat space 名・人名・業務側の識別子・個人メールの局部など)は
すべてここへ置く。** 本ファイルへ書けば公開リポジトリへ名前を載せることになる。ローカル拡張ファイルから読み足す。

- 置き場所: `config/public_repo_forbidden_words.local.txt`(script の位置から見た `../config/`。
  OSS 側の `.gitignore`〈`*` で全除外〉により追跡されない。privategit 側で管理する)。
- 書式: **1行に ERE の断片を1つ**。空行と、先頭が `#` の行(前に空白があってもよい)は無視する。
  行末の CR は無視する。各行は `(断片)` に包まれ、公開側の正規表現(番兵)と `|` で結合される。
- 読込: ファイルが**存在すれば追加、無ければ無視**(ここまではエラーにしない)。存在するのに読めない、
  または断片が不正な ERE のときは、黙って素通りさせずエラー終了する(fail-closed)。
- ★ただし**公開側が番兵のみ**の現行運用では、ローカル拡張が無い(または有効な語が0行の)まま走らせると、
  上記「fail-closed」で終了コード 2 になる。走査を使う前にローカル拡張を用意すること
  (無い環境では privategit から復元するか、将軍へ依頼する)。
- 一時的に別の場所を使う(試験・検証)ときは `--words-file <file>` / `--local-ext <file>` を指定する。
